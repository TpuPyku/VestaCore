# VestaCore

Общие модули для программ на штатной ГУ Lada Vesta (Windows CE 6.0, ARM): **VestaHome**, **VestaLaunch** и **OSMapsCE**.
Код компилируется прямо в каждую программу (без DLL), поэтому каждая работает сама по себе, а вместе —
делят ресурсы ГУ.

Подключение: git submodule в папку `core\` репозитория программы (после клонирования —
`git submodule update --init`); `build.bat` программы берёт `core\`, а если его нет — папку `VestaCore`,
лежащую рядом с репозиторием программы. Только Win32 (COREDLL на CE), VS2005, без C++11.

## Модули

### `vgps` — GPS и поток CAN-модуля, общий для нескольких программ
- Читает порт ГУ (COM5 — копия потока CAN-модуля, 115200) только на чтение, настройки порта не трогает
  (скорость — только если задана и отличается), опрос через `ClearCommError`.
- NMEA: `$xxRMC` (позиция, скорость, курс, дата/время UTC), `$xxGGA` (спутники, высота); контрольная сумма
  проверяется, без неё строка принимается только полной.
- Строки CAN-модуля (как их читает G3NavHMI, `rn2::CanMessageParser`): `@,<скорость км/ч>,<версия>*hh`,
  `@ANG,<угол руля | null>,*hh`; без контрольной суммы не принимаются (копия порта теряет байты).
- **Общий доступ**: именованный мьютекс `VestaGPS_Owner` — кто его взял, тот читает порт и публикует состояние и
  последние 64 проверенные строки в общую память `VestaGPS` (sequence lock); остальные копируют оттуда.
  Закрылась или упала читающая программа — мьютекс освобождается, порт подхватывает следующая.
- «Отводы» для мониторов: каждая проверенная строка (всегда) и сырые байты (пока программа читает порт).
- Поиск порта (COM1..COM9, без смены скорости), смена порта на лету, ПК: `<файл>.nmea` проигрывает запись.

API — `vgps.h`: `GpsStart(&GpsConfig)`, `GpsStop`, `GpsGet(&GpsState)`, `GpsConfigure`, `GpsScan`.

### `vlogdir` — куда писать журналы
- Только съёмные носители: SD-карта (`\SDMemory\VestaLogs\`) или USB-диск (`\USB Disk`, `\USBDisk`,
  `\USBDevice`); во встроенную флеш-память ГУ (`\SDMMC`, `\ResidentFlash`, `\StorageFlash`) — никогда,
  она изнашивается. Без носителя журнала нет; носитель ищется заново раз в 30 с. На ПК — папка программы.

API — `vlogdir.h`: `LogDir(dir, exeDir)`.

### `vtask` — диспетчер задач
- Процессы через `toolhelp.dll` (загружается при запуске, без списков куч — `TH32CS_SNAPNOHEAPS`): имя,
  потоки, загрузка ЦП (сумма `GetThreadTimes` потоков процесса за период), память (закоммиченные личные
  страницы, `VirtualQueryEx`, раз в 3 замера).
- Общая загрузка ЦП — `GetIdleTime` (на ПК `GetSystemTimes`), память — `GlobalMemoryStatus`; история
  из 60 замеров для графиков.
- Окна верхнего уровня с заголовком (без рабочего стола и панели задач) и их процессы.
- Сортировка (имя, ЦП, память, PID), завершение процесса (системные процессы CE и саму программу — нельзя).
- В фоне ничего не работает: замеры делает сама программа (раз в 1–2 с, пока экран открыт).

API — `vtask.h`: `TaskSample(&TaskInfo, self)`, `TaskSort`, `TaskKill`, `TaskIsSystem`.
